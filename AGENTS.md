# Webflow Marketplace – Library Submission Guide (Simplified)

## 1. Quality Criteria (Non-negotiable)

Every submission is manually reviewed by the Webflow Marketplace team.

They evaluate:

- Design quality (visual polish, consistency, usability)
- Functionality (everything works as described)
- Clarity (easy to understand and reuse)
- Alignment with Webflow standards

Important: “Satisfactory” submissions may get feedback, but if you don’t reach “Good” quality after 2 feedback rounds, the library can be rejected.

## 2. Getting Started

Before building:

- Decide the purpose of your library (layouts, components, sections, UI system, etc.)
- Ensure it solves a clear, repeatable problem for Webflow users
- Keep the scope focused (avoid bloated “do-everything” libraries)

## 3. Create Your Layouts

### Supported Elements

You should stick to native, reusable Webflow elements, such as:

- Sections, Containers, Divs
- Headings, Text blocks, Buttons
- Forms (basic, reusable)
- CMS collections (if clearly documented)
- Utility classes and variables (used consistently)

### Unsupported Elements & Features

Avoid:

- Custom code dependencies that break portability
- Hard-coded content users must delete to use the layout
- Experimental or unstable Webflow features
- Overly complex interactions without documentation

## 4. Demo Site (Required)

You must provide a live demo site that:

- Shows every layout/component clearly
- Uses real-world example content (not lorem everywhere)
- Demonstrates responsiveness (desktop, tablet, mobile)
- Matches exactly what’s in the library

Think of it as a showroom, not a playground.

## 5. Design Guidelines

Your library should:

- Follow a consistent visual system
- Use spacing, typography, and colors intentionally
- Be accessible (contrast, readable font sizes)
- Feel modern, clean, and professional

Even “unstyled” or minimal libraries must feel intentional.

## 6. Naming Conventions

Clarity > cleverness.

- Classes should be readable and predictable
- Use consistent prefixes (e.g. lib-, ui-, section-)
- Avoid cryptic or auto-generated class names
- Components and layouts should be easy to identify at a glance

## 7. Licensing

You must:

- Clearly state the license (free, commercial, usage rights)
- Ensure you own or have rights to all assets (icons, fonts, images)
- Avoid copyrighted or restricted materials unless licensed properly

## 8. Recommended Practices (Strongly Encouraged)

These improve approval odds:

- Clear documentation or README
- Logical class structure
- Minimal overrides needed by users
- Reusability across different projects
- Thoughtful empty states for CMS components

## 9. Submit Your Library

Before submitting:

- Double-check everything matches the demo
- Test cloning and reuse from a fresh account/project
- Review Webflow’s Creator Agreement
- Be prepared to revise based on feedback

## Pre-Submission Checklist (Quick Scan)

- Looks professional and intentional
- Works without breaking or extra setup
- Clear naming and structure
- Demo site matches the library
- No unsupported features
- Licensing is clear
- Solves a real use case
